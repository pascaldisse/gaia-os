Status: SPEC ONLY (recon lane). Zone A code = opus lane's; this file = its work

## §0 Ground (all read-only, file:line)

- Font: `shrine/Kernel/FontStd.HC:3` — `U64 sys_font_std[256]`, one U64/glyph.
  Encoding (verified vs '/','T',':' glyphs): byte n of the U64 (LSB-first) =
  pixel row n, top→bottom; bit m of that byte = column m, **bit 0 = leftmost**.
  → `pixel(x,y) = (glyph >> (y*8 + x)) & 1`. Coverage: full 0-255; ASCII
  32-126 canonical; 0-6 = Temple frame/box glyphs; ≥128 accents/Cyrillic-style
  extras. Peer file `shrine/Kernel/FontCyrillic.HC` (same 132-line shape,
  alternate table). Consumed upstream: `shrine/Kernel/KMain.HC:67`
  (`text.font=sys_font_std;`), `shrine/Apps/Lsh.HC:419`.
- Palette: `shrine/Adam/Gr/GrPalette.HC:64-68` — `CBGR48 gr_palette_std[16]`,
  fields b,g,r = low/mid/high U16 (verified: idx1=0x...AAAA→BLUE,
  idx4=0xAAAA0000_0000→RED, idx6=0xAAAA5555_0000→BROWN AA5500).
- Recomposite model (later rung): `shrine/Adam/WinMgr.HC:266-271` — WinMgr task
  paced by `WINMGR_PERIOD`, calls `GrUpdateScrn` (:271), `winmgr.updates++`
  (:307), fps calc (:231-234). `shrine/Adam/Gr/GrScrn.HC:399` — "Called by the
  Window Manager … 30 times a second"; `GrScrn.HC:3-4` `Refresh` waits on it.
- Our fb: `kernel-arm/zoneA/fw_cfg.c` — `FbInit` :132 (MAlloc'd XRGB8888
  linear buffer, `0x00RRGGBB` per :107 comment, stride px = FB_WIDTH :91),
  exports `FbBase`/`FbWidth` :129-130, `dsb sy` publish pattern (fw_dma
  :64-71 + FbDrawPattern closing dsb). Geometry: `kernel.h:45-47`
  `FB_WIDTH 640 / FB_HEIGHT 480 / FB_BPP 4`.
- UART path: `kmain.c:10-15` — `putc` = PL011 poll+store; `puts` = loop putc,
  inserts '\r' before '\n'. Everything prints through these two.
  FbInit hook site: `kmain.c:860` `if (FbInit() == 0) FbDrawPattern();`.
- HolyC export precedent: `zcmod.c:70-77` — `zc_resolve` static name→addr map
  (`KPutS`,`FbBase`,`FbWidth`); modules carry `{rip,name}` import tables,
  patched at link (`zcmod.c:90,:152,:166`). GaiaPlot = proven FbBase/FbWidth
  consumer.
- Shell: `shell.c:99` `run_cmd` verb chain, `:29` `cmd_help`, prompt loop
  `:326` (`puts("\n"); run_cmd; puts("T:/> ")`), backspace echo `"\b \b"`.
- Gate: `kernel-arm/zoneA/scratch/ramfb_gate.py` — serial socket drives verbs,
  QEMU monitor `screendump` → PPM, `px(x,y)` + `near(tol=10)` checks.

## §1 Font provenance road

Converter: NEW `kernel-arm/zoneA/tools/mkfont.py` — parse the
`U64 <name>[256]= { … };` initializer block (regex hex literals, expect exactly
256), emit `font_std.c`. Source file = parameter (default
`shrine/Kernel/FontStd.HC`; FontCyrillic swappable later). Zero deps beyond
python3 stdlib.

Emitted file: NEW `kernel-arm/zoneA/font_std.c`:

```c
// Generated by tools/mkfont.py from shrine/Kernel/FontStd.HC
// (TempleOS, Terry A. Davis, public domain — see shrine/LICENSE).
// Encoding: byte n = row n top->bottom, bit m = col m, LSB = leftmost.
// Regenerate: python3 tools/mkfont.py   (output is stable; diff must be empty)
#include "kernel.h"
const u64 sys_font_std[FONT_GLYPHS] = { /* 256 literals */ };
```

RULE — **commit the generated array as source.** Justification:
- 2 KB static data, frozen upstream (the Temple font will never change) →
  regenerating each build buys nothing, costs a build-time python3 + shrine/
  tree dependency in an otherwise bare cross-compile (`build.sh`).
- Provenance stays auditable: header comment cites generator + source +
  license; converter committed beside it → reproducibility one command away.
- Exact repo precedent: `zcmod.c:1-3` commits generated machine-code byte
  arrays with provenance comments. Same law, same shape.
Gitignored-generated rejected: adds a moving part to every clean build for a
constant.

## §2 gr.c design — glyph blitter + console

NEW `kernel-arm/zoneA/gr.c`. Geometry ALL parameterized (IRON — zero magic
640s; every varying value a const w/ default), added to `kernel.h`:

```c
#define GLYPH_W  8                    // Temple font cell
#define GLYPH_H  8
#define FONT_GLYPHS 256
#define GR_COLS  (FB_WIDTH  / GLYPH_W)   // 80 @ defaults
#define GR_ROWS  (FB_HEIGHT / GLYPH_H)   // 60 @ defaults
#define GR_DEF_FG 15                  // WHITE
#define GR_DEF_BG 0                   // BLACK
#define GR_CON_DEFAULT 1              // fb console on after FbInit success
```

Palette table (gr.c): `static const u32 gr_palette[16]` — Temple index →
XRGB8888, derived from `gr_palette_std` CBGR48 by high-byte-per-channel
(`(r>>8)<<16 | (g>>8)<<8 | (b>>8)`):

```
0 BLACK  0x000000   4 RED    0xAA0000   8  DKGRAY   0x555555  12 LTRED    0xFF5555
1 BLUE   0x0000AA   5 PURPLE 0xAA00AA   9  LTBLUE   0x5555FF  13 LTPURPLE 0xFF55FF
2 GREEN  0x00AA00   6 BROWN  0xAA5500   10 LTGREEN  0x55FF55  14 YELLOW   0xFFFF55
3 CYAN   0x00AAAA   7 LTGRAY 0xAAAAAA   11 LTCYAN   0x55FFFF  15 WHITE    0xFFFFFF
```

API (kernel.h decls; `long` args on exported fns = HolyC I64 ABI, mirrors
`FbBase` returning long):

```c
void GrCls(long bg);                                  // fill fb w/ palette[bg&15], cursor home
void GrPutChar(long col, long row, long ch, long fg, long bg);  // stateless cell blit
void GrPuts(const char *s);                           // stateful console write (fb only)
void GrConsoleEnable(int on);   int GrConsoleEnabled(void);
void GrConPutc(char c);                               // stateful single char (tee target, §3)
```

Blitter core (GrPutChar): needs fb pointer → gr.c gets it via
`(u32 *)FbBase()`; no-op while fb==0 (pre-FbInit safety).

```c
u32 *cell = fb + (u64)row * GLYPH_H * FB_WIDTH + (u64)col * GLYPH_W;
u64 g = sys_font_std[ch & (FONT_GLYPHS - 1)];
for (y = 0; y < GLYPH_H; y++) {
    u32 *px = cell + (u64)y * FB_WIDTH;
    u32 bits = (g >> (y * 8)) & 0xFF;
    for (x = 0; x < GLYPH_W; x++)
        px[x] = (bits >> x) & 1 ? gr_palette[fg & 15] : gr_palette[bg & 15];
}
```

Bounds: col ≥ GR_COLS or row ≥ GR_ROWS → return (no clip math, cells only).

Console state (gr.c statics): `cur_col, cur_row`, `con_fg = GR_DEF_FG`,
`con_bg = GR_DEF_BG`, `con_on = 0` (armed at boot, §3). `GrConPutc`:
- `'\n'` → col=0, row+1;  `'\r'` → col=0;  `'\b'` → col>0 → col-1 (erase falls
  out of shell's existing `"\b \b"` sequence, shell.c echo);
- other c < 32 → ignore (console law; raw Temple glyphs 0-6 stay reachable via
  stateless GrPutChar);
- printable → GrPutChar(cur_col, cur_row, c, con_fg, con_bg), col+1; col ==
  GR_COLS → wrap (col=0, row+1).
- row == GR_ROWS → **scroll one glyph row**: memmove semantics via forward
  u64 copy loop (no libc in zone A; dst < src → forward copy overlap-safe):
  `(FB_HEIGHT - GLYPH_H) * FB_WIDTH` px moved up by `GLYPH_H * FB_WIDTH`,
  then last text row filled with `gr_palette[con_bg]`; row = GR_ROWS-1.
- tail: `dsb sy` (publish pattern, fw_cfg.c fw_dma/FbDrawPattern). Per-char
  dsb is fine at serial rate; GrPuts may hoist to one dsb after the loop.

No drawn cursor v1 (later rung, §5).

## §3 Console tee — UART always, fb toggleable

Hook point = `putc` (kmain.c:10), NOT puts: everything (puts, putdec, puthex,
shell keystroke echo) funnels through putc, so one hook tees it all:

```c
void putc(char c) { /* existing PL011 store */ if (GrConsoleEnabled()) GrConPutc(c); }
```

puts stays untouched (its inserted '\r' is harmless: GrConPutc '\r' = col=0,
then '\n' advances row). UART is NEVER silenced — serial gates unaffected.

Boot arming: `kmain.c:860` becomes
`if (FbInit() == 0) { FbDrawPattern(); GrConsoleEnable(GR_CON_DEFAULT); }`
→ default face ON (GR_CON_DEFAULT=1): banner + prompt land on screen from
first boot. Flip the one define if the lane wants pattern-first boots.

Shell verbs (run_cmd, shell.c:99 + help :29):
- `fbcon` / `fbcon on` / `fbcon off` — bare = print status; on/off = toggle.
  Ack on UART+fb: `fbcon: on|off`.
- `cls` — `GrCls(GR_DEF_BG)`, **prints nothing** (silent → next prompt lands
  deterministically at row 0; test plan §6 depends on this).

Interaction w/ `fb` verb: FbDrawPattern overpaints console cells; console
keeps writing over the pattern afterward — accepted (test plan orders around
it).

Temple code then prints natively: a future module carries

(open question §7).

## §5 Later rung — 30 Hz recomposite + DolDoc (honest, out of scope)

What Temple actually does is retained-mode: every task owns a document, and a
dedicated WinMgr task wakes on WINMGR_PERIOD (WinMgr.HC:266-271), walks the
task windows, recomposites them into an off-screen buffer, and GrUpdateScrn /
GrUpdateScreen (GrScrn.HC:399) pushes that to the fb 30 times a second —
`Refresh` (GrScrn.HC:3) just waits for the next pass. Getting there from here
needs: retained per-task text/cell buffers instead of write-through blits, a
timer-paced compositor task on our cooperative task.c (ticks + Yield exist,
pacing discipline doesn't), a shadow buffer + copy (doubles fb memory,
needs the dirty-rect thinking GrScrn does), and for DolDoc the whole Doc
engine — documents-with-links-and-sprites is an Adam-layer port that wants a
far more mature zoneC HolyC runtime, not a kernel primitive. Not now because
the immediate-mode console is one file, gate-testable this week, and — by
design — already the "raw blit" layer a future compositor would sit on top
of; nothing speced here has to change shape when the WinMgr rung comes.

## §6 Test plan — ramfb_gate.py extensions (SPEC ONLY, gate not touched here)

Extend `kernel-arm/zoneA/scratch/ramfb_gate.py`, same socket/screendump rig,
same `near(tol=10)`.

Phase A — pattern regression (existing 7 checks, kept green):
1. boot, drain banner
2. send `fbcon off\r` (console default-ON would otherwise paint prompt text
   over pattern pixels after redraw)
3. send `fb\r`, screendump #1 → existing corner/bar checks UNCHANGED.

Phase B — glyph checks:
4. send `fbcon on\r`, then `cls\r` → GrCls homes cursor, silent verb, shell
   prints `T:/> ` → prompt glyphs land exactly at cells (0..4, 0), fg WHITE
   bg BLACK defaults.
5. screendump #2 → checks (cell (c,r) = pixels x∈[c*8,c*8+7], y∈[r*8,r*8+7];
   'T' = 0x001818181818187E → row0 0x7E, rows1-6 0x18; ':' =
   0x0018180018180000 → rows2,3,5,6 = 0x18):

```
("T top bar",   px(1,0),  (255,255,255))   # 'T' row0 bit1
("T stem",      px(3,1),  (255,255,255))   # 'T' row1 bit3
("T corner bg", px(0,0),  (0,0,0))         # 'T' row0 bit0 clear
("colon dot",   px(11,2), (255,255,255))   # ':' cell1, row2 bit3
("colon top bg",px(11,0), (0,0,0))         # ':' row0 empty
("space cell",  px(35,3), (0,0,0))         # ' ' cell4 all bg
```

6. serial asserts: `fbcon: off` / `fbcon: on` acks present; banner still fully
   on UART (tee never silences serial).

   GrPutChar only — revisit when DolDoc rung wants them.
